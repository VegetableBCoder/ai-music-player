# Agent 经验库

本目录沉淀**可复用的操作经验**，供后续 Agent 在执行前参考。文件按操作类型划分。

## 怎么用（Agent 必读）

1. **动手前先读匹配的经验文件** —— 根 `AGENTS.md` 有索引表，按任务类型找。
2. **按经验执行**，不要重复踩过的坑（尤其那些"看起来像 X、实际是 Y"的）。
3. **发现经验与现状不符时，先判定属于哪一类，再分别处理**：

   | 判定 | 含义 | 处理 |
   | --- | --- | --- |
   | **跨平台差异** | 换了 OS / 设备 / 版本，事实变了 | **补全**：加分平台、分设备的分支，**保留**旧结论 |
   | **经验本身写错了** | 当时的结论就错（误判了根因） | **修复**：改正 + 记下纠正原因，别只删原文 |
   | **过时** | 事实作废（换机、升级） | **标注作废**并给替代做法，保留一行历史 |

   判定方法：**先复现，再定性**。同一条命令在两个环境下结果不同 → 跨平台差异；
   在所有环境下都不成立 → 经验本身错了。
4. 修完经验回到 `AGENTS.md` 看索引是否还准；新增文件要登记进索引表。

## 记一条经验的格式

- **症状** —— 观察到的现象，含准确的报错 / 日志 / 命令输出。
- **根因** —— 真正的机制，以及**它为什么会被误判成别的东西**（这段最值钱）。
- **做法** —— 可直接执行的命令 / 代码。
- **复核** —— 怎么确认真的生效了。**不要用"构建成功"当证据**。
- **环境** —— 结论成立的前提（OS / 设备 / 版本）。跨平台的结论必须写清适用范围。
