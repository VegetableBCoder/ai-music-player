# 2. 开发顺序

**原则**：按依赖方向自底向上（`core` → `feature`），因为底层契约（`02 §5`）一旦实现错，上层全部返工。
每阶段必须**同时交付实现 + 测试**，并通过该阶段验收才进入下一阶段。

**交付原则（调整）：垂直切片 —— 界面跟着它的功能走，不攒到最后。**

原计划是「Phase 3~7 全做引擎、Phase 8 才做界面」，结果是中间**五个阶段只能看测试、无法动手验证**。
Phase 3 就是现成的例子：引擎做完、116 条测试全绿，但手机上点不到「开始扫描」。
调整后：**每个引擎阶段末尾就交付能操作的界面**。`09` 已把 17 个屏的 `UiState` / 事件 / `ViewModel`
（含 `ScanViewModel` §3.3.3）全部定稿，所以这不是新的设计工作，只是把对应的屏前移；
界面**直接按 `09` 正式稿做**，Phase 8 只做横切部分，不返工。

| 阶段 | 随之交付的界面（`09 §3.2`） |
| --- | --- |
| 3 文件扫描 | `ScanScreen`(3.2.9)+ `LyricDirsScreen`(3.2.11) |
| 4 分析 + LLM | `AnalysisRunScreen`(3.2.10)+ `SettingsScreen`(3.2.13) |
| 5 歌曲库与标签 | 3.2.1~3.2.7 + `SongDetailScreen`(3.2.17) |
| 6 播放器 | `PlayerScreen`(3.2.14)+ `QueueScreen`(3.2.16)+ mini 条 + 底部导航 |
| 7 歌词 | 歌词页(3.2.15) |
| 8 横切 | 导航图收口、三件套打磨、空状态映射逐条、可访问性、`RecentPlayedScreen`(3.2.12) |

**连带前移**（原属 Phase 8/9，不提前界面就走不通）：`:app` 的 Manifest 权限声明（`10 §3.1`）、
`:app` 的 `PermissionChecker` / `PermissionLauncher`（`10 §4.2`）、最小 Hilt 装配（`10 §5.4`）、
一条最小的导航 + 底部导航壳（`09 §4.1` / `§4.4`）。

# 3. 每阶段的完成定义（DoD）

一个阶段算"完成"，必须同时满足：

1. 实现按文档对应章节落地，**契约签名与 `02 §5` 逐字一致**（不得自创命名，见 `02 §3.2` / `§11`）。
2. 该文档 §8「测试要点」的项目有对应测试且通过。
3. `./gradlew assembleDebug` 与 `./gradlew test` 全绿。
4. 涉及数据库的，`I1–I12` 不受破坏。
5. **该阶段涉及的用户路径，真机上能在界面里走通**（垂直切片之后，这个问题不再有"无 UI 阶段"的例外；纯底层阶段——如 `:core:common`——仍可用 adb/logcat 验证）。
6. 文档与实现不一致处，**改文档**（文档是锁定的契约，不能默默偏离）。
