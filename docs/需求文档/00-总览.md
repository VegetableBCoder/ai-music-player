# 音乐播放器需求文档 · 总览

> 版本：V1.0
> 本文档为整体需求基线，包含四个模块：歌曲库管理、播放器、歌词、智能标签。

---

# 1. 核心概念

## 1.1 音乐文件

设备上的音频文件，是扫描的对象。记录文件位置、格式、大小、时长、内嵌元数据。

音乐文件仅作为歌曲来源，不作为用户主要管理对象。

## 1.2 歌曲实体（歌曲）

音乐库的核心管理对象。标签、歌词、播放记录均归属歌曲实体，而不是归属音乐文件。

### 实体身份键

```
entityKey = ( 规范化歌名 , 排序去重后的规范化演唱者集合 )
```

- **规范化歌名**：去首尾空格、统一大小写与全半角；**保留版本语义词**（Live / Remix / 伴奏 / 现场 / 翻唱 / 原唱 / Instrumental 等），这些词用于区分不同录音。
- **规范化演唱者**：取**全部署名演唱者**，由 LLM 统一处理分隔符与角色词（`feat.` / `with` / `&` / `/` / `、`）后，排序、去重成集合。
- **比较**：对上述两个字段做**精确相等**判定，相等即为同一首歌、归属同一实体。
- 歌手别名（如 `Jay Chou` / `周杰伦` / `周董`）由 LLM 在分析阶段归一到规范名。
- 纯音乐同样带有演奏者信息（如 坂本龙一、泽野弘之），按演唱者处理，不存在"演唱者为空"的特殊情况。

示例：

| 文件元数据 | entityKey |
| --- | --- |
| 晴天 - 周杰伦 | (晴天, [周杰伦]) |
| 晴天 - 周杰伦（原唱） | (晴天, [周杰伦]) |
| 晴天 - 张三（翻唱） | (晴天, [张三]) |
| 小酒窝 - 林俊杰 & 蔡卓妍 | (小酒窝, [林俊杰, 蔡卓妍]) |
| 小酒窝 - 蔡卓妍、林俊杰 | (小酒窝, [林俊杰, 蔡卓妍]) |
| 晴天 (Live) - 周杰伦 | (晴天(live), [周杰伦]) |

> 注：本表描述的是**端到端结果**（LLM 归一 + 本地规范化叠加），并非 `TextNormalizer` 单独的输出。三点容易误读：
> 1. **演唱者集合按 Unicode 码位排序**（`03 §4.5`：不做拼音排序），故写作 `[林俊杰, 蔡卓妍]`（林 U+6797 < 蔡 U+8521），而非拼音顺序。
> 2. 本地归一化只做「大小写 / 全半角 / 空白折叠 / 去标点两侧空格」，**括号等标点保留**，故 `晴天 (Live)` 归一为 `晴天(live)`；版本语义词不剥离，因此它与 `晴天` 不是同一实体。
> 3. **`原唱` / `翻唱` 这类中文角色词由 LLM 剥离**（见 §1.2 正文），`TextNormalizer` 只处理本地可判定的分隔符与拉丁角色词（`feat.` / `ft.` / `with` / `vs.` / `&` / `/` / `、`）。所以 `周杰伦（原唱）` → `周杰伦` 靠的是 LLM，不是本地归一化。

## 1.3 代表文件

一个歌曲实体可关联多个音乐文件（重复文件、不同来源等）。

- 播放与实体信息展示以**体积最大的文件**作为代表文件（不按编码、码率等衡量音质）。
- 代表文件被删除后，自动回退到次大的文件。

## 1.4 标签

歌曲实体的附属信息，用于分类与检索。详见 `04-智能标签.md`。

## 1.5 歌词

歌曲实体的附属信息，与歌曲绑定，而不是与具体文件绑定。详见 `03-歌词.md`。

## 1.6 不可用歌曲

当歌曲实体**没有任何可用文件**时，该歌曲为不可用歌曲。

- 不可用歌曲**不得加入播放队列**。
- 列表中仍展示，但置灰 / 不可点击（点击只提示"无可用文件"）。

# 2. 实体与文件的关系规则

- 重新扫描**不重建实体**。文件分析后按以下规则挂靠：
  - 归一化输出（entityKey）与已有实体一致 → 将该文件记录加入该实体的文件清单；
  - 否则 → 新建实体。
- 一个文件同一时间只属于一个实体。
- 已经关联实体的文件**不支持重新分析**；未关联实体的文件可以分析。
- **不做实体合并**。错误关联的纠正方式：手动删除该实体，文件回到未关联状态后可重新分析。
- **已知残留**：`A` 与 `A feat. B`（同一录音的不同署名）会被拆成两个实体，V1 不做合并。

---

# 3. 展示信息与元数据来源

- **歌手列表（展示）** = 实体身份的规范化演唱者集合。
- **专辑名称、发行日期、封面** = 代表文件内嵌元数据。
- **专辑歌手 / 合辑「多位歌手」判定** = 由 LLM 归一化确定。
- **时长**：歌曲列表不展示；播放时展示正在播放的文件时长；歌词匹配使用代表文件时长。
- 代表文件发生变化时，上述展示信息随之切换到新的代表文件。

# 4. 扫描与分析流水线

## 4.1 扫描

- 发现本地音乐文件，**并索引音乐来源目录及外部歌词目录下的 `.lrc` 文件**。
- 记录：文件位置、格式、大小、时长、内嵌元数据。
- 触发：首次使用扫描、用户主动重新扫描。
- 用户可管理播放器可访问的音乐来源。

## 4.2 分析

- 一次 LLM 调用：输入 **文件名 + 元数据** → 输出 **归一化数据（entityKey）+ 标签信息**。
- 标签关联对象为歌曲实体。

## 4.3 分析状态机

| 状态 | 说明 |
| --- | --- |
| 未分析 | 已入库，等待分析 |
| 分析中 | 正在调用分析 |
| 已关联 | 分析成功，已挂到实体。**终态，不重分析** |
| 分析失败 | 出错且未自动恢复。**可手动重试** |

- **429** → 自动指数退避重试（1s → 2s → 4s … 上限 60s，重试上限 N 次）；退避期间保持「分析中 / 排队」，不计失败。
- **其他错误** → 不自动处理，置「分析失败」，提供手动重试。

## 4.4 触发流程

1. 扫描完成 → 与已记录文件比对 → 提示「发现 N 个新文件」+ 摘要（新增 N / 已存在跳过 M / 已删除清理 K）。
2. **「分析并添加」** → 文件入库（状态：未分析）→ 进入分析进度。
3. **「放弃」** → 文件**不入库、不留记录**；下次扫描会重新作为新文件提示。

## 4.5 失败与清理

- 扫描时发现文件已删除 → 自动清除该文件记录。
- 播放时文件缺失 → 提示并清理该记录；若删除的是代表文件，回退到次大文件；若实体再无文件，提示是否删除（可选择**保留并标记为不可用**）。
- 不主动监听文件移动、重命名、内容变化。

## 4.6 界面

- **扫描结果提示**：摘要 + 「分析并添加」/「放弃」。
- **分析进度**：进度 + 本次分析的文件清单与状态（未分析 / 分析中 / 已关联〔所属歌曲〕/ 失败〔原因〕），失败可重试；「查看详情」进入完整文件列表（触发分析 / 重试失败 / 移除记录 / 物理删除）。
- **常驻入口（二级）**：**文件扫描 → 最近分析记录**，查看最近一次分析的结果摘要与文件清单/状态，可继续操作失败 / 未分析项。

# 5. 删除模型

统一按「主表删除 + 清理不可达关联」处理。

| 操作 | 影响 | 确认级别 |
| --- | --- | --- |
| **删除歌曲实体** | 级联删除以实体为归属的关联数据：标签关联、歌词关联、以歌曲为键的播放历史/统计。**不影响磁盘上的音乐文件与 `.lrc` 文件** | 实体**有文件**时才二次确认；无文件直接删除 |
| **移除文件**（解除关联） | 将文件从实体文件清单移除，磁盘文件保留；若为最后一个文件 → 自动删除实体 | 明显提示；若为最后一个文件，额外提示"将同时删除该歌曲" |
| **物理删除文件** | 从磁盘永久删除文件，用于清理重复文件；若为代表文件 → 回退次大文件；若为最后一个文件 → 自动删除实体 | 用户确认（破坏性，不可恢复） |

- 标签 → 歌曲数量是即时派生计数，随删除自然更新；标签维度的聚合统计属于远期能力，不受影响。
- 三类删除使用同一套确认组件与文案风格；**V1 不做撤销 / 回收站**。

| 物理删除文件 | 删除磁盘上的文件 | "移除" |
